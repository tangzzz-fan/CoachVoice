# CoachVoice

训练中的「教练语音」方向。从 SportsHelper（DongKe）的播报需求长出来的独立实验场。

**一句话定位：** 不追实时语音模型，做「事件驱动 + 构建期渲染 + 运行时拼接」的教练语音管线——
用可控的封闭词表换 20ms 首音、零耗电、零回落。

## 现在到哪了（2026-10-26）

调研完成，**还没有一行业务代码**。已确认三件事：

1. Apple Workout Buddy 的「动态」拆开是三层：话术由 LLM 现写、音色是训练死的、合成靠语义音频 token。三层里只有第一层是真动态。
2. 第三方在 iOS 上拿不到任何「训练自己的音色」的 API；端侧中文 TTS 的 RTF ≈ 1，够不上 4 秒播报预算。
3. 所以这条路不跟 Apple 比模型，比的是**语料**（谁来演）和**时机**（什么时候说）。

## 设计前提（不满足就别做）

- **封闭词表**：播报文案是有界集合（现 496 条短语），运行时只做切句 + 拼接。自由文本不进播报。
- **一节课一种音色**：任何一句回落到系统 TTS，听感立刻变成两个人。
- **情绪由事件选，不由模型即兴**：`calm`（组间）/ `encourage`（达标）/ `push`（最后一组、破纪录）。
- **预算按秒**：中文 4.0–4.3 字/秒，单句 ≤4 秒 / 20 字，超预算先丢修饰语。

第 1 项预期就是死刑——写出来是为了以后别再有人问「为什么不用端侧大模型」。

## 非目标

- 不做端侧实时 TTS（RTF 不够，见报告 §3 墙 2）
- 不做自由文本生成播报（会被 3B 模型的中文口语质量反噬）
- 不碰真人教练声纹（声音权 + 深度合成标识，必须有书面授权）
